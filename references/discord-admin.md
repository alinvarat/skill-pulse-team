# การดูแลเซิร์ฟเวอร์และแอป Discord ของ PULSE

- งานปรับโครงสร้างเซิร์ฟเวอร์ Discord (roles/channels) ทำผ่าน REST ด้วย token ของโปรไฟล์ที่เกี่ยวข้อง (อ่านจาก `.env` โดยไม่แสดงค่า) ลำดับ: 1) `GET /users/@me` ยืนยันว่าเป็นบอตที่ถูกตัว 2) `POST /guilds/{guild}/roles` สร้างบทบาท (ได้ id) 3) `PUT /guilds/{guild}/members/{bot_id}/roles/{role_id}` มอบบทบาทให้บอตแต่ละตัว (204 = สำเร็จ) 4) `GET /guilds/{guild}/members` ยืนยันผล
  - สร้างห้อง/หมวด: `POST /guilds/{guild}/channels` ด้วย `{"name","type":0,"parent_id":<id หมวด>}` (type 4 = หมวด) ลบห้องหรือหมวดว่างด้วย `DELETE /channels/{id}` ก่อนลบต้องตรวจว่าไม่มีห้องข้างในและไม่ใช่ห้องที่มีข้อความสำคัญ
  - โพสต์ข้อความด้วย `POST /channels/{id}/messages` ทุกครั้งต้องส่ง header `User-Agent: DiscordBot (<ชื่อ>, <เวอร์ชัน>)` ตามที่ Discord กำหนด และตัดข้อความไม่ให้เกิน 2000 ตัวอักษรต่อข้อความ (ยาวกว่านี้จะถูกปฏิเสธ) แบ่งเป็นหลายข้อความแทน
  - ตรวจสิทธิ์ก่อนลงมือ: REST ตอบ 403 `50013 Missing Permissions` เมื่อบอตขาด Manage Roles/Channels และบอตขยายสิทธิ์ให้ตัวเองไม่ได้ ทางที่ใช้ได้คือให้เจ้าของเปิด "จัดการบทบาท" ให้บอตหนึ่งครั้งในหน้าตั้งค่าเซิร์ฟเวอร์ (บทบาท → เลือกบทบาทของบอต → การอนุญาต) หรือเจ้าของล็อกอินเว็บในแท็บที่ Chief เปิดไว้ (ห้ามกรอกรหัสผ่านแทน) แล้วทำต่อในแท็บเดิม
  - หลังแก้สิทธิ์ใน UI ต้องกด "บันทึกการเปลี่ยนแปลง" ให้เสร็จก่อน ไม่งั้นแถบ unsaved ค้างและ REST ยังได้ 50013 เพราะสิทธิ์ยังไม่มีผล
  - ใช้ GUI เฉพาะขั้นที่ REST ทำไม่ได้ (การเปิดสิทธิ์); สร้าง/มอบ role ด้วย REST ต่อ และไม่ต้องตั้งชื่อรายการ UI ซ้ำ
- เชิญบอตเข้าเซิร์ฟเวอร์: ใช้ URL `https://discord.com/oauth2/authorize?client_id=<APP_ID>&scope=bot%20applications.commands&permissions=117824&guild_id=<guild>` เปิดใน Chrome หลักแล้วยืนยันหน้าสำเร็จจาก capture (ปุ่ม "อนุญาต" ต้องได้รับอนุมัติก่อนกดตามกติกาของ debian-desktop-control) APP_ID ต้องอ่านจากหน้า portal แบบ full-res ไม่ใช่จาก screenshot ย่อ ห้ามยืนยันว่าเชิญสำเร็จถ้ายังไม่เห็นหน้าสำเร็จหรือไม่เห็นบอตในรายชื่อสมาชิก
- Message Content Intent เปิดได้เฉพาะเจ้าของแอปในหน้า Bot ของ portal; ถ้า scroll ใน portal ไม่ขยับให้หยุดแล้วส่งรายการให้เจ้าของเปิดเอง อย่าไล่คลิกต่อ
- อาการ `discord_intents_required` ใน `gateway_state.json` (สถานะ fatal ของโปรไฟล์) หมายถึง Message Content Intent ปิดอยู่ ยืนยันก่อนลงมือ GUI ด้วย `GET https://discord.com/api/v10/applications/@me` ด้วย Bot token ของโปรไฟล์นั้น (ใส่ User-Agent) แล้วดู `flags`: bit `1<<18` = Message Content (full) ต้องเป็น 1 ถ้า `flags` ยังไม่มี bit นี้ ให้เปิดที่หน้า Bot ของ application นั้นแล้วกด Save Changes; หลังบันทึก ให้ตรวจ flags อีกรอบและรีสตาร์ท gateway ผ่าน detached background ตามคู่มือ อย่าสรุปว่าแก้แล้วจากหน้าจอที่ยังไม่ได้ปิดไปจริง
- การเปิดสิทธิ์ใน Developer Portal เป็นการเปลี่ยนค่าที่เจ้าของต้องอนุมัติ: ขออนุมัติผ่านการ์ดก่อน ถ้าการ์ดหมดเวลาหรือไม่ตอบ ให้หยุดและรายงานสถานะ (flags และรายชื่อบอตที่ยังค้าง) พร้อมลิงก์หน้า Bot ของแต่ละแอป ห้ามทำต่อเงียบ ๆ

## สร้างแอปบอต
- สร้างแอปบอตใน Discord Developer Portal: ตรวจ grid แอปก่อนทุกครั้ง (ชื่อซ้ำเกิดได้เมื่อกด Create ซ้ำ) และถ้ามี hCaptcha ขึ้นให้หยุดให้เจ้าของทำ แล้วทำต่อในแท็บเดิม; ใช้เบราว์เซอร์หลักที่ล็อกอินอยู่ (ไม่ใช่เบราว์เซอร์ browser_exec ที่มักยังไม่ล็อกอิน) ถ้าคลิกบนหน้า portal ไม่ได้หรือไม่มี session ล็อกอิน ให้บอกเจ้าของเป็นรายการขั้นตอน (กด "แอปพลิเคชันใหม่" ตั้งชื่อ → แท็บ Bot → Reset Token) แล้วรอ token ที่เจ้าของใส่ `.env` ของโปรไฟล์เอง ห้ามเดาหรือขอให้วาง token ในแชต ไม่จัดการรหัสผ่าน OTP CAPTCHA หรือเปิดเผย tokens
